Setup by AI agents

Everything you can do in the dashboard, an AI agent (or a script) can do over the API with an account key. A person creates the key once; the agent does the rest. This page is the exact sequence of calls.

For agents: this page is also available as plain text in /llms-full.txt (with the full API reference), and the API as OpenAPI 3.1. All requests and responses are JSON. Send Content-Type: application/json with every request body.

0. What the person does

  1. Sign in at /app/login with Google.
  2. Go to /app/account and create an account key. Copy it; it's shown once.
  3. Give the agent two values, as environment variables or secrets (never in a repository): 
    export JEF_URL="https://jef.example.com"
export JEF_ACCOUNT_KEY="jef_acct_…"

An account key can do anything the account owner can: create and delete apps, keys and rules, set webhooks, link Discord servers, read usage, and create Stripe Checkout or billing portal links. It can't pay; payment always happens on a Stripe page a person opens. Revoke it at /app/account (or DELETE /v1/keys/{keyId}) when the agent is done.

The game itself should use an app key (jef_app_…), which can only moderate for one app. Don't put the account key in game servers or clients.

1. Check the key and the plan

curl -s "$JEF_URL/v1/account" -H "Authorization: Bearer $JEF_ACCOUNT_KEY"
{
  "account": { "id": "acct_Qm3x…", "email": "owner@example.com", "name": "Sam", "plan": "free",
               "subscriptionStatus": null, "currentPeriodEnd": null, "createdAt": "2026-10-01T09:12:44.000Z" },
  "limits": { "id": "free", "name": "Free", "priceUsd": 0, "apps": 1, "accountKeys": 1, "aiChecksPerMonth": 2000,
              "customRules": 3, "historyDays": 7, "webhooks": false, "requestsPerSecond": 5 },
  "usage": { "month": "2026-10", "messages": 0, "aiChecks": 0, "apps": 0, "accountKeys": 1 },
  "admin": false,
  "auth": "account_key"
}

Check auth is "account_key" (an app key returns "app_key" and can't do setup). Compare usage.apps with limits.apps and limits.customRules with the number of rules you plan to add, before creating anything. In limits, null means unlimited.

2. Look for an existing app first

POST /v1/apps isn't idempotent: calling it twice makes two apps. Before creating one, list the apps and reuse one with the same name.

curl -s "$JEF_URL/v1/apps" -H "Authorization: Bearer $JEF_ACCOUNT_KEY" \
  | jq -r '.apps[] | select(.name == "My Game") | .id'

If the app exists, skip to step 4. You can't read an existing key's secret again; if you need one, create a new app key (POST /v1/apps/{appId}/keys) and delete the old one.

3. Create the app with rules and a key

One call creates an API app, its custom rules, optionally its webhook, and its first app key:

curl -s "$JEF_URL/v1/apps" \
  -H "Authorization: Bearer $JEF_ACCOUNT_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "My Game",
    "kind": "api",
    "rules": [
      { "text": "No sharing real-world addresses, phone numbers or other personal details", "severity": "high" },
      { "text": "No begging other players for items or currency", "severity": "low" }
    ]
  }'

Response (201):

{
  "app": {
    "id": "app_Xk2mP9qLr4Tz",
    "name": "My Game",
    "kind": "api",
    "discordGuildId": null,
    "settings": {},
    "webhookUrl": null,
    "webhookSecret": null,
    "inPlan": true,
    "rules": [
      { "id": 41, "text": "No sharing real-world addresses, phone numbers or other personal details", "severity": "high", "createdAt": "2026-10-08T12:00:00.000Z" },
      { "id": 42, "text": "No begging other players for items or currency", "severity": "low", "createdAt": "2026-10-08T12:00:00.000Z" }
    ],
    "createdAt": "2026-10-08T12:00:00.000Z"
  },
  "appKey": {
    "key": { "id": "key_7hQ2pW0sLmAa", "kind": "app", "appId": "app_Xk2mP9qLr4Tz", "name": "Default key",
             "prefix": "jef_app_3kq9", "createdAt": "2026-10-08T12:00:00.000Z", "lastUsedAt": null },
    "secret": "jef_app_3kq9…"
  }
}
  • Save appKey.secret immediately (for example into the game server's secret store as JEF_APP_KEY). It is never shown again.
  • Fields: name (required, up to 80 characters), kind ("api" or "discord", default "api"), rules (each text up to 300 characters, severity low | medium | high, default low), webhookUrl (paid plans), createKey (default true; false skips the app key).
  • The whole call fails if anything is invalid or over a limit, and nothing is created: too many apps or rules give 403 plan_limit.

4. Add or change rules

Write rules in plain words, the way you'd explain them to a moderator. The severity decides the punishment (ladder).

# add
curl -s "$JEF_URL/v1/apps/$APP_ID/rules" \
  -H "Authorization: Bearer $JEF_ACCOUNT_KEY" -H "Content-Type: application/json" \
  -d '{"text": "No spoilers for the new season in general chat", "severity": "low"}'
# → 201 { "rule": { "id": 43, "text": "…", "severity": "low", "createdAt": "…" } }

# list
curl -s "$JEF_URL/v1/apps/$APP_ID/rules" -H "Authorization: Bearer $JEF_ACCOUNT_KEY"
# → { "rules": [ … ] }

# remove (no body; 204 on success, 404 not_found if it's already gone)
curl -s -X DELETE "$JEF_URL/v1/apps/$APP_ID/rules/43" -H "Authorization: Bearer $JEF_ACCOUNT_KEY"

There's no "edit rule" call: to change a rule, add the new one, then delete the old one. To make rules idempotent, list them first and only add texts that aren't there yet.

5. Set a webhook

Starter and Pro only (on Free: 403 plan_limit). The URL must be public https://.

curl -s -X PATCH "$JEF_URL/v1/apps/$APP_ID" \
  -H "Authorization: Bearer $JEF_ACCOUNT_KEY" -H "Content-Type: application/json" \
  -d '{"webhookUrl": "https://game.example.com/hooks/jef"}'
# → { "app": { …, "webhookUrl": "https://game.example.com/hooks/jef", "webhookSecret": "whsec_…" } }

Store app.webhookSecret where the receiver can verify signatures (see webhooks). You can read it again with GET /v1/apps/{appId} using the account key. Rotate it with POST /v1/apps/{appId}/webhook-secret; remove the webhook with {"webhookUrl": null}.

6. Link a Discord server

Linking needs a person with Manage Server on the Discord server; the agent prepares everything and hands over one link.

curl -s "$JEF_URL/v1/apps" \
  -H "Authorization: Bearer $JEF_ACCOUNT_KEY" -H "Content-Type: application/json" \
  -d '{"name": "My Discord", "kind": "discord", "rules": [{"text": "No posting game cheats or exploits", "severity": "medium"}]}'
{
  "app": { "id": "app_Dc9…", "kind": "discord", "discordGuildId": null, … },
  "discord": {
    "inviteUrl": "https://discord.com/oauth2/authorize?client_id=…&permissions=…&scope=bot+applications.commands&response_type=code&redirect_uri=…&state=A1B2C3D4E5F6",
    "linkCode": "A1B2C3D4E5F6",
    "linkCommand": "/jef link code:A1B2C3D4E5F6",
    "expiresAt": "2026-10-08T13:00:00.000Z",
    "autoLink": true
  }
}
  1. Give the person discord.inviteUrl. When autoLink is true, adding the bot with it links the server automatically, but only if that person is signed in to the dashboard, in the same browser, as the account owner when Discord sends them back (otherwise the dashboard shows reason=signed_out or not_owner and nothing is linked). If that's not the case, or autoLink is false, or the bot is already in the server, they run discord.linkCommand in the server instead. Give them both.
  2. Wait until it's linked: poll GET /v1/apps/{appId} every few seconds until app.discordGuildId isn't null.
  3. The code expires at expiresAt (1 hour). For a fresh one: POST /v1/apps/{appId}/discord/link (same discord object; the old code stops working).
  4. Optionally set the mod log channel and exemptions with PATCH /v1/apps/{appId} {"settings": {"modLogChannelId": "…", "ignoredChannelIds": […], "exemptRoleIds": […]}}, or have the person run /modlog.

inviteUrl is null if the server operator hasn't configured a Discord bot.

7. Test moderation

With the account key, pass appId; with the app key you don't need it.

curl -s "$JEF_URL/v1/moderate" \
  -H "Authorization: Bearer $JEF_APP_KEY" -H "Content-Type: application/json" \
  -d '{"userId": "setup-test-user", "username": "SetupTest", "text": "you are an idiot", "room": "test"}' \
  | jq '{allow, category, severity, action: .action.type, label: .action.label}'
# → { "allow": false, "category": "rudeness", "severity": "medium", "action": "mute", "label": "10 minute mute" }

Test calls are real: they count toward usage and give the test user strikes. Clear them afterwards:

curl -s "$JEF_URL/v1/apps/$APP_ID/users/setup-test-user/pardon" \
  -H "Authorization: Bearer $JEF_ACCOUNT_KEY" -H "Content-Type: application/json" -d '{}'
# → { "removed": 1, "strikes": 0 }

Then wire the call into the game server as in the game chat quickstart.

8. Check usage

curl -s "$JEF_URL/v1/account" -H "Authorization: Bearer $JEF_ACCOUNT_KEY" \
  | jq '{plan: .account.plan, aiChecks: .usage.aiChecks, aiLimit: .limits.aiChecksPerMonth, messages: .usage.messages, month: .usage.month}'

Usage is per account (all apps together) and per calendar month in UTC. At most a tenth of aiChecksPerMonth (rounded up) can be used in one UTC day. Past either limit, moderation keeps working on the free checks only until it resets, and /v1/moderate responses include "aiSkipped": "quota" where the AI was skipped.

Also check that every app has "inPlan": true (in GET /v1/apps). After a downgrade, apps past the plan's count (newest first) have inPlan: false, aren't moderated, and /v1/moderate on them returns 403 plan_limit. Likewise only each app's oldest customRules rules apply, and account keys past the plan's accountKeys (newest first) get 403 plan_limit on every request.

9. Upgrade (a person pays)

An agent can't pay, but it can prepare the payment page. Check billing first:

curl -s "$JEF_URL/v1/billing" -H "Authorization: Bearer $JEF_ACCOUNT_KEY"
# → { "enabled": true, "plan": "free", "subscriptionStatus": null, "currentPeriodEnd": null, "hasCustomer": false }

Then get a link for the person:

curl -s "$JEF_URL/v1/billing/checkout" \
  -H "Authorization: Bearer $JEF_ACCOUNT_KEY" -H "Content-Type: application/json" \
  -d '{"plan": "starter"}'
# → { "url": "https://checkout.stripe.com/c/pay/…", "kind": "checkout" }
  • Give url to the person to open. When they've paid, GET /v1/account shows the new plan (usually within seconds). Poll it rather than assuming.
  • If the account already has a subscription, the response is "kind": "portal" and the URL is the Stripe customer portal, where they switch plans. Don't create a second subscription.
  • plan must be "starter" or "pro" (anything else: 400 invalid_request). If billing isn't set up on the server: 503 billing_unavailable; enabled: false in GET /v1/billing says so in advance.
  • To cancel, change card or see invoices: POST /v1/billing/portal → { "url" } (400 no_customer if they never subscribed).

Errors and retries

Every error is JSON: { "error": { "code": "plan_limit", "message": "The Free plan allows 1 app(s). Delete one or upgrade." } }. Branch on code; show message to people.

StatuscodeWhat to do
400invalid_request, invalid_jsonFix the request; the message names the field. Don't retry unchanged.
400no_customerUse /v1/billing/checkout instead of the portal.
401invalid_api_key, unauthorizedThe key is wrong or revoked, or missing. Ask the person for a new account key.
403forbiddenYou used an app key for something that needs the account key.
403plan_limit, limitOver the plan's limit (apps, account keys, rules, webhooks) or the 10 app keys per app. Also: moderating an app that's past the plan's app count, or using an account key that's past the plan's key count. Delete something or ask the person to upgrade (step 9).
404not_foundNo such app, key or rule on this account (or an unknown endpoint). Re-list and use current IDs.
409guild_takenThat Discord server is linked to another app.
413too_largeRequest bodies are limited to 64 KB.
429rate_limitedToo many /v1/moderate calls for the app. Wait for Retry-After (1 second), then retry, doubling the wait if it repeats.
500internalRetry later with backoff.
502 / 503billing_error, billing_unavailableStripe failed, or billing isn't configured. Retry later or tell the person.

Safe to retry: every GET, PATCH (same body, same result) and DELETE (a second delete gives 404, which you can treat as done). Not safe to blindly retry: POST /v1/apps, /keys, /rules, /warn (they create things); list first, then decide. There's no idempotency-key header.

A complete setup script

Idempotent: run it again and it reuses the app and only adds missing rules. Needs curl and jq.

#!/usr/bin/env bash
# Usage: JEF_URL=… JEF_ACCOUNT_KEY=jef_acct_… ./setup-jef.sh
set -euo pipefail
APP_NAME="My Game"
RULES='[
  {"text": "No sharing real-world addresses, phone numbers or other personal details", "severity": "high"},
  {"text": "No begging other players for items or currency", "severity": "low"}
]'

api() { # api METHOD PATH [JSON]
  local args=(-sS -X "$1" "$JEF_URL$2" -H "Authorization: Bearer $JEF_ACCOUNT_KEY" -w '\n%{http_code}')
  [ $# -ge 3 ] && args+=(-H "Content-Type: application/json" -d "$3")
  local out code; out=$(curl "${args[@]}"); code=${out##*$'\n'}; out=${out%$'\n'*}
  if [ "$code" -ge 400 ]; then echo "$1 $2 → $code $out" >&2; return 1; fi
  printf '%s' "$out"
}

[ "$(api GET /v1/account | jq -r .auth)" = account_key ] || { echo "JEF_ACCOUNT_KEY is not an account key" >&2; exit 1; }

APP_ID=$(api GET /v1/apps | jq -r --arg n "$APP_NAME" '[.apps[] | select(.name == $n and .kind == "api")][0].id // empty')
if [ -z "$APP_ID" ]; then
  CREATED=$(api POST /v1/apps "$(jq -n --arg n "$APP_NAME" --argjson r "$RULES" '{name: $n, kind: "api", rules: $r}')")
  APP_ID=$(jq -r .app.id <<<"$CREATED")
  echo "Created $APP_ID. App key (store it now, it is shown once):"
  jq -r .appKey.secret <<<"$CREATED"
else
  echo "Using existing app $APP_ID"
  EXISTING=$(api GET "/v1/apps/$APP_ID/rules" | jq -c '[.rules[].text]')
  jq -c '.[]' <<<"$RULES" | while read -r rule; do
    if ! jq -e --argjson t "$(jq '.text' <<<"$rule")" 'index($t)' <<<"$EXISTING" >/dev/null; then
      api POST "/v1/apps/$APP_ID/rules" "$rule" >/dev/null && echo "Added rule: $(jq -r .text <<<"$rule")"
    fi
  done
fi

api GET /v1/account | jq '{plan: .account.plan, usage: .usage, limits: {apps: .limits.apps, aiChecksPerMonth: .limits.aiChecksPerMonth}}'
