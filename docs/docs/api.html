API reference

The /v1 JSON API, used by games, agents and the dashboard alike. Also available as OpenAPI 3.1.

On this page
  • Basics: authentication, errors, rate limits, pagination
  • Objects
  • Endpoints: public, account, account keys, apps, app keys, Discord linking, rules, moderate, users, history, billing

Basics

  • Base URL: this site's address, e.g. https://jef.example.com/v1.
  • Bodies are JSON: send Content-Type: application/json. Bodies are limited to 64 KB.
  • Timestamps are ISO 8601 strings in UTC, e.g. "2026-10-08T12:00:00.000Z". Durations are milliseconds.
  • IDs are strings (acct_…, app_…, key_…), except rule, strike and event IDs, which are integers.
  • CORS: /v1 answers cross-origin requests that carry an API key. Even so, don't put keys in browsers or game clients.

Authentication

Send an API key as a bearer token:

Authorization: Bearer jef_acct_…
CredentialScope
Account key jef_acct_…Everything on the account, including billing links. Create at /app/account or POST /v1/keys. If the account has more account keys than its plan allows (after a downgrade), the newest ones past the limit get 403 plan_limit on every request.
App key jef_app_…One API app: POST /v1/moderate, GET /v1/account, and the app's GET app / rules / users / events, …/warn and …/pardon. Anything else is 403 forbidden.
Session cookie jef_sessionThe dashboard, after Google sign-in. Same rights as an account key. Requests that change data must be same-origin and Content-Type: application/json (otherwise 403 bad_origin or 415 json_required).

In the tables below, Auth is none, account (account key or session) or any (account key, session, or that app's own app key). A request with an Authorization header that isn't a valid key fails with 401 invalid_api_key, even on public endpoints.

Rate limits

POST /v1/moderate is limited per app, by the owner's plan: 5 (Free), 20 (Starter) or 50 (Pro) requests per second, as a token bucket that allows bursts of up to twice that. Over the limit: 429 rate_limited with a Retry-After: 1 header. Other endpoints have no per-plan rate limit, but please keep setup traffic modest.

Pagination

Only history (GET /v1/apps/{appId}/events) is paginated. It returns events newest first and a nextBefore cursor: pass it as ?before= to get the next (older) page. Stop when a page has fewer events than limit or is empty. Other lists return everything at once.

Objects

Account

{ "id": "acct_Qm3x…", "email": "owner@example.com", "name": "Sam", "plan": "starter",
  "subscriptionStatus": "active", "currentPeriodEnd": "2026-11-08T12:00:00.000Z", "createdAt": "2026-10-01T09:12:44.000Z" }

plan: free, starter, pro or internal (operator accounts; unlimited). subscriptionStatus is Stripe's (active, past_due, canceled, …) or null.

Plan limits

{ "id": "free", "name": "Free", "priceUsd": 0, "apps": 1, "accountKeys": 1, "aiChecksPerMonth": 2000,
  "customRules": 3, "historyDays": 7, "webhooks": false, "requestsPerSecond": 5 }

In GET /v1/account, null means unlimited. GET /v1/plans items also have purchasable (whether this server can sell the plan).

Key

{ "id": "key_7hQ2pW0sLmAa", "kind": "app", "appId": "app_Xk2mP9qLr4Tz", "name": "Default key",
  "prefix": "jef_app_3kq9", "createdAt": "2026-10-08T12:00:00.000Z", "lastUsedAt": null }

kind: account (then appId is null) or app. prefix is the first characters of the secret, to tell keys apart. lastUsedAt is updated at most once a minute. The secret itself is only returned once, at creation, next to the key: { "key": Key, "secret": "jef_…" }.

App

{
  "id": "app_Xk2mP9qLr4Tz",
  "name": "My Game",
  "kind": "api",
  "discordGuildId": null,
  "settings": {},
  "webhookUrl": "https://game.example.com/hooks/jef",
  "webhookSecret": "whsec_…",
  "inPlan": true,
  "rules": [ Rule, … ],
  "createdAt": "2026-10-08T12:00:00.000Z"
}
  • kind: api or discord. discordGuildId: the linked Discord server ID, or null.
  • settings (Discord apps): modLogChannelId (string), ignoredChannelIds, exemptRoleIds (arrays of IDs). Unset settings are absent.
  • webhookSecret is omitted when you read the app with an app key.
  • inPlan: whether the app is within the plan's app count. Apps are counted oldest first; after a downgrade, newer apps past the limit are false and aren't moderated (POST /v1/moderate gives 403 plan_limit, Discord messages are ignored) until you delete apps or upgrade.
  • rules lists all the app's rules, but only the oldest ones up to the plan's customRules are applied.

Rule

{ "id": 41, "text": "No begging other players for items or currency", "severity": "low", "createdAt": "2026-10-08T12:00:00.000Z" }

Strike

{ "id": 812, "at": "2026-10-08T12:00:00.000Z", "until": "2026-10-09T12:00:00.000Z", "category": "rudeness",
  "severity": "medium", "reason": "Insulting another member", "excerpt": "you are such an idiot, uninstall", "by": "auto" }

until: when it stops counting. excerpt: up to 200 characters (null for manual warnings). by: "auto", or who issued a manual warning.

Event

{ "id": 5531, "at": "2026-10-08T12:00:00.000Z", "type": "action", "userId": "player_18842", "username": "Tobi",
  "room": "lobby-3", "messageId": "msg_99120", "excerpt": "you are such an idiot, uninstall", "category": "rudeness",
  "severity": "medium", "reason": "Insulting another member", "source": "rules", "action": "10 minute mute",
  "strikes": 1, "by": null }

type: action (automatic punishment), watch (possible griefing or bullying, no action), manual (a warn) or pardon. Fields that don't apply are null. excerpt is up to 500 characters; action is the punishment's label. For Discord apps, room is the channel name (e.g. #general).

Public

GET/v1/health

Auth: none. { "ok": true }.

GET/v1/plans

Auth: none. { "plans": [Plan limits + purchasable] } for Free, Starter and Pro.

Account

GET/v1/account

Auth: any. The account that owns the credential, its plan limits and this month's usage.

{
  "account": Account,
  "limits": Plan limits,
  "usage": { "month": "2026-10", "messages": 1834, "aiChecks": 412, "apps": 2, "accountKeys": 1 },
  "admin": false,
  "auth": "account_key"
}

usage.messages and usage.aiChecks are for the current UTC month, across all apps. auth: session, account_key or app_key.

Account keys

GET/v1/keys

Auth: account. { "keys": [Key] }, account keys only, oldest first.

POST/v1/keys

Auth: account. Body { "name"?: string ≤ 60 } (default "Account key"). 201 { "key": Key, "secret": "jef_acct_…" }. 403 plan_limit past the plan's account keys.

DELETE/v1/keys/{keyId}

Auth: account. 204. Works on the key making the request, too.

Apps

GET/v1/apps

Auth: account. { "apps": [App] }, oldest first.

POST/v1/apps

Auth: account. Creates an app, and in the same transaction its rules and webhook.

FieldType
namestring ≤ 80Required.
kind"api" | "discord"Default "api".
rules[{ text ≤ 300, severity? }]Up to the plan's custom rules. Severity defaults to low.
webhookUrlstringPublic https:// URL. Paid plans.
createKeybooleanAPI apps: create a first app key (default true). Ignored for Discord apps.

201:

{
  "app": App,
  "appKey": { "key": Key, "secret": "jef_app_…" },                // API apps, unless createKey is false
  "discord": { "inviteUrl": "https://discord.com/oauth2/authorize?…" | null,   // Discord apps
               "linkCode": "A1B2C3D4E5F6", "linkCommand": "/jef link code:A1B2C3D4E5F6",
               "expiresAt": "2026-10-08T13:00:00.000Z", "autoLink": true }
}

GET/v1/apps/{appId}

Auth: any. { "app": App } (no webhookSecret with an app key).

PATCH/v1/apps/{appId}

Auth: account. Only the fields you send change. { "app": App }.

FieldType
namestring ≤ 80
webhookUrlstring | nullPaid plans. Setting one the first time also creates webhookSecret. null or "" removes it.
settingsobjectDiscord apps only. modLogChannelId: a channel ID; ignoredChannelIds, exemptRoleIds: up to 100 IDs. IDs are 5–25 digit strings. Merged into the current settings; null clears one. Unknown keys: 400.

DELETE/v1/apps/{appId}

Auth: account. 204. Deletes the app with its rules, keys, strikes and history. A linked Discord server stops being moderated.

POST/v1/apps/{appId}/webhook-secret

Auth: account. Replaces the signing secret: { "webhookSecret": "whsec_…" }. The old one stops working immediately.

App keys

GET/v1/apps/{appId}/keys

Auth: account. { "keys": [Key] }.

POST/v1/apps/{appId}/keys

Auth: account. API apps only (Discord apps: 400). Body { "name"?: string ≤ 60 } (default "App key"). 201 { "key": Key, "secret": "jef_app_…" }. At most 10 per app (403 limit).

DELETE/v1/apps/{appId}/keys/{keyId}

Auth: account. 204.

Discord linking

POST/v1/apps/{appId}/discord/link

Auth: account. Discord apps only. A new invite link and link code, valid 1 hour; earlier codes for the app stop working.

{ "inviteUrl": "https://discord.com/oauth2/authorize?…", "linkCode": "A1B2C3D4E5F6",
  "linkCommand": "/jef link code:A1B2C3D4E5F6", "expiresAt": "2026-10-08T13:00:00.000Z", "autoLink": true }

autoLink: adding the bot with inviteUrl links the server by itself, provided the person is signed in to the dashboard as the app's owner when Discord redirects back (otherwise it fails with reason=signed_out or not_owner); else run linkCommand in the server. inviteUrl is null if the server has no Discord bot configured. When linked, app.discordGuildId is set.

DELETE/v1/apps/{appId}/discord

Auth: account. 204. Unlinks the server; the bot stays in it but stops moderating. Strikes and history are kept.

Custom rules

GET/v1/apps/{appId}/rules

Auth: any. { "rules": [Rule] }.

POST/v1/apps/{appId}/rules

Auth: account. Body { "text": string ≤ 300, "severity"?: "low" | "medium" | "high" } (default low). 201 { "rule": Rule }. 403 plan_limit past the plan's custom rules. Only the app's oldest rules up to that limit are applied.

DELETE/v1/apps/{appId}/rules/{ruleId}

Auth: account. 204, or 404 if there's no such rule.

Moderate

POST/v1/moderate

Auth: any. Judges one message, records the strike and history if it broke a rule, and returns a moderation result. Rate limited per app (429 with Retry-After: 1). 403 plan_limit if the app has inPlan: false.

FieldType
appIdstringRequired with an account key or session; optional with an app key (must match it).
userIdstring ≤ 100Required. Stable ID of the sender (numbers are accepted and turned into strings).
textstring ≤ 4000Required. The message.
usernamestring ≤ 100Display name.
messageIdstring ≤ 100Your message ID; referenced in deleteMessages later.
roomstring ≤ 100Channel or lobby. The last 5 messages per room are kept in memory as context.
replyTostring ≤ 400 | { username ≤ 100, text ≤ 300 }The message being replied to.
contextarray ≤ 20 of string ≤ 400 | { username ≤ 100, text ≤ 300 }Earlier messages, oldest first. Replaces the remembered room context.
 
curl -s https://jef.example.com/v1/moderate \
  -H "Authorization: Bearer $JEF_APP_KEY" -H "Content-Type: application/json" \
  -d '{"userId": "player_18842", "username": "Tobi", "text": "gg everyone", "messageId": "msg_99121", "room": "lobby-3",
       "context": [{"username": "Mia", "text": "close game!"}]}'

Every call counts as a message in usage; it counts as an AI check only if it reached the AI (a griefing or bullying pattern check is one more). If the app has a webhook and the plan includes webhooks, a punishment also sends moderation.action.

Users

A "user" is any userId you've sent; there's nothing to create. For Discord apps, it's the Discord user ID.

GET/v1/apps/{appId}/users/{userId}

Auth: any. Active strikes, and what the next offense of each severity would bring.

{
  "userId": "player_18842",
  "strikes": 1,
  "active": [ Strike ],
  "next": {
    "low":    { "type": "mute", "label": "10 minute mute", "durationMs": 600000, "message": "…" },
    "medium": { "type": "mute", "label": "1 hour mute", "durationMs": 3600000, "message": "…" },
    "high":   { "type": "ban", "label": "Ban", "durationMs": null, "message": "…" }
  }
}

POST/v1/apps/{appId}/users/{userId}/warn

Auth: any. A manual punishment on the same ladder. Body { "reason": string ≤ 300, "severity"?: … (default medium), "username"?: string ≤ 100, "by"?: string ≤ 100 }. by defaults to the signed-in email or the key's name. Returns { "strikes": 2, "action": Action }; your game applies the action. Sends moderation.manual.

For Discord apps, a warn through the API records the strike but doesn't time the member out or DM them; use /warn in Discord for that.

POST/v1/apps/{appId}/users/{userId}/pardon

Auth: any. Removes the newest count active strikes, or all of them. Body { "count"?: positive integer, "by"?: string ≤ 100 }. Returns { "removed": 1, "strikes": 0 }. Sends moderation.pardon. It doesn't lift a mute or ban already applied; do that in your game (or in Discord).

History

GET/v1/apps/{appId}/events

Auth: any. Newest first. Kept for the plan's historyDays.

Query
limitInteger, default 50, clamped to 1–200.
beforeInteger event ID: only events older than it. Use the previous page's nextBefore.
userIdOnly this user's events.
 
{ "events": [ Event, … ], "nextBefore": 5480 }

nextBefore is the ID of the last event on the page (null if the page is empty).

Billing

Account keys and sessions only (app keys: 403). Payment always happens on a Stripe page that a person opens.

GET/v1/billing

{ "enabled": true, "plan": "starter", "subscriptionStatus": "active",
  "currentPeriodEnd": "2026-11-08T12:00:00.000Z", "hasCustomer": true }

enabled: this server can take payments. hasCustomer: the account has subscribed before (so the portal works).

POST/v1/billing/checkout

Body { "plan": "starter" | "pro" }. Returns { "url": "https://checkout.stripe.com/…", "kind": "checkout" }. If the account already has a live subscription, returns { "url": "https://billing.stripe.com/…", "kind": "portal" } instead, to change plan there. After paying, the person returns to /app/account and the plan updates within seconds. Errors: 400 invalid_request (other plan, or an internal account), 503 billing_unavailable, 502 billing_error.

POST/v1/billing/portal

No body. { "url": "https://billing.stripe.com/…" }: the Stripe customer portal to change plan, update the card, see invoices or cancel. 400 no_customer before the first purchase.
