Game chat quickstart

Moderate your game's chat in five minutes. Your game server sends each chat message to Jef Bot and gets back what to do: let it through, or remove it and mute or ban the player.

On this page
  • 1. Create an API app
  • 2. Send each message to /v1/moderate
  • 3. Read the verdict
  • 4. Enforce it in your game
  • Show first, or wait for the verdict?
  • Tips and gotchas

Call Jef Bot from your game server, never from the game client. Anything shipped to players (a game build, a web page, a mobile app) can be unpacked, and the key with it. Clients send chat to your server as usual; your server asks Jef Bot and decides what to broadcast.

1. Create an API app

In the dashboard: sign in, create an app of kind API (a game or other app), and copy the app key (jef_app_…) it shows you. The key is shown only once; store it as a secret on your game server, for example in an environment variable JEF_APP_KEY.

Or with the API, using an account key from /app/account:

curl -s https://jef.example.com/v1/apps \
  -H "Authorization: Bearer $JEF_ACCOUNT_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name": "My Game", "kind": "api"}'

The response has the app and its first app key. appKey.secret is the only time you'll see the full key:

{
  "app": { "id": "app_Xk2mP9qLr4Tz", "name": "My Game", "kind": "api", "rules": [], ... },
  "appKey": {
    "key": { "id": "key_7hQ2pW0sLmAa", "kind": "app", "appId": "app_Xk2mP9qLr4Tz", "name": "Default key", "prefix": "jef_app_3kq9", ... },
    "secret": "jef_app_3kq9…"
  }
}

2. Send each message to /v1/moderate

For every chat message a player sends, your server calls POST /v1/moderate with the app key. With an app key you don't need to send appId.

FieldWhat to send
userIdrequiredThe player's stable ID (account ID, not display name), up to 100 characters. Strikes are counted per userId, so if it changes, their record resets.
textrequiredThe message, up to 4,000 characters.
usernameoptionalDisplay name, up to 100 characters. Shown in history and to the AI as context.
messageIdrecommendedYour ID for this message, up to 100 characters. Needed if you want deleteMessages to point at earlier messages you can find again. If you leave it out, Jef Bot makes one up.
roomrecommendedThe chat channel, lobby or match ID, up to 100 characters. Jef Bot remembers the last few messages per room and gives them to the AI as context.
replyTooptionalWhat the message replies to: a string (up to 400) or { "username", "text" }.
contextoptionalUp to 20 earlier messages, oldest first, as strings (up to 400 each) or { "username", "text" }. Overrides the remembered room context.
 
curl -s https://jef.example.com/v1/moderate \
  -H "Authorization: Bearer $JEF_APP_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "userId": "player_18842",
    "username": "Tobi",
    "text": "you are such an idiot, uninstall",
    "messageId": "msg_99120",
    "room": "lobby-3"
  }'
// Node 18+ (built-in fetch). Runs on your game server.
const JEF_URL = 'https://jef.example.com';
const JEF_APP_KEY = process.env.JEF_APP_KEY;

export async function moderate({ userId, username, text, messageId, room }) {
  const res = await fetch(`${JEF_URL}/v1/moderate`, {
    method: 'POST',
    headers: { Authorization: `Bearer ${JEF_APP_KEY}`, 'Content-Type': 'application/json' },
    body: JSON.stringify({ userId, username, text, messageId, room }),
    signal: AbortSignal.timeout(10_000),
  });
  if (!res.ok) {
    const { error } = await res.json().catch(() => ({}));
    throw new Error(`Jef Bot ${res.status}: ${error?.code} ${error?.message}`);
  }
  return res.json(); // { allow, action, reason, deleteMessages, ... }
}

import os
import requests

JEF_URL = "https://jef.example.com"
JEF_APP_KEY = os.environ["JEF_APP_KEY"]

def moderate(user_id, username, text, message_id=None, room=None):
    res = requests.post(
        f"{JEF_URL}/v1/moderate",
        headers={"Authorization": f"Bearer {JEF_APP_KEY}"},
        json={"userId": user_id, "username": username, "text": text,
              "messageId": message_id, "room": room},
        timeout=10,
    )
    if not res.ok:
        err = res.json().get("error", {}) if res.headers.get("content-type", "").startswith("application/json") else {}
        raise RuntimeError(f"Jef Bot {res.status_code}: {err.get('code')} {err.get('message')}")
    return res.json()  # {"allow": ..., "action": {...}, ...}
// .NET 6+. Runs on your game server (not in the Unity client).
using System.Net.Http.Headers;
using System.Net.Http.Json;
using System.Text.Json;

public static class JefBot
{
    static readonly HttpClient Http = new() { BaseAddress = new Uri("https://jef.example.com"), Timeout = TimeSpan.FromSeconds(10) };

    static JefBot()
    {
        Http.DefaultRequestHeaders.Authorization =
            new AuthenticationHeaderValue("Bearer", Environment.GetEnvironmentVariable("JEF_APP_KEY"));
    }

    public static async Task<JsonElement> Moderate(string userId, string username, string text, string messageId, string room)
    {
        var res = await Http.PostAsJsonAsync("/v1/moderate", new { userId, username, text, messageId, room });
        var body = await res.Content.ReadFromJsonAsync<JsonElement>();
        if (!res.IsSuccessStatusCode)
            throw new Exception($"Jef Bot {(int)res.StatusCode}: {body.GetProperty("error").GetProperty("code")}");
        return body; // body.GetProperty("allow").GetBoolean(), body.GetProperty("action") ...
    }
}
-- Pseudocode for a Lua game server; adapt to your engine's HTTP and JSON libraries.
local function moderate(player, text, messageId, room)
  local res = http.post(JEF_URL .. "/v1/moderate", {
    headers = { Authorization = "Bearer " .. JEF_APP_KEY, ["Content-Type"] = "application/json" },
    body = json.encode({ userId = player.accountId, username = player.name,
                         text = text, messageId = messageId, room = room }),
    timeout = 10,
  })
  if res.status ~= 200 then return nil, res.body end
  return json.decode(res.body)
end

3. Read the verdict

A clean message:

{
  "messageId": "msg_99121",
  "allow": true,
  "flagged": false,
  "category": null,
  "severity": null,
  "reason": null,
  "source": "jev",
  "action": { "type": "none", "label": "No action", "durationMs": null, "message": null },
  "strikes": 0,
  "deleteMessages": [],
  "watch": null
}

A message that breaks the rules:

{
  "messageId": "msg_99120",
  "allow": false,
  "flagged": true,
  "category": "rudeness",
  "severity": "medium",
  "reason": "Insulting another member",
  "source": "rules",
  "action": {
    "type": "mute",
    "label": "10 minute mute",
    "durationMs": 600000,
    "message": "That crossed the line. You have been muted for 10 minutes.",
    "level": 1
  },
  "strikes": 1,
  "deleteMessages": [],
  "watch": null
}
FieldMeaning
allowtrue: the message is fine. false: remove it (or don't show it).
action.typenone, delete (remove the message only), mute (remove and mute for action.durationMs) or ban (remove and ban; durationMs is null).
action.messageA ready-made message for the player, e.g. "You have been muted for 10 minutes." null for none and delete.
reasonShort reason, safe to show the player ("Insulting another member", "Server rule: …").
category, severityWhat kind of rule was broken and how badly (low, medium, high). See rules.
strikesThe player's active strikes after this message.
deleteMessagesEarlier messages to remove too: [{ "messageId", "room" }]. Filled for spam waves (the earlier copies) and scams (the rest of the scam run).
watch"griefing" or "harassment" when the message looks like the start of a pattern. No action yet; it's noted in history. Otherwise null.
sourceWhat decided: spam, rules (keywords and scam patterns), jev or ai (Claude, on self-hosted servers configured that way).
aiSkippedOnly present as "quota" when your monthly AI checks are used up and only the free checks ran.

4. Enforce it in your game

Jef Bot tells you what to do; your game does it. Jef Bot doesn't remember mutes or bans for you (it remembers strikes), so keep a mutedUntil per player on your side.

async function onChat(player, text, room) {
  if (Date.now() < (player.mutedUntil ?? 0)) return player.tell('You are muted.');
  if (player.banned) return;

  const messageId = crypto.randomUUID();
  let verdict;
  try {
    verdict = await moderate({ userId: player.accountId, username: player.name, text, messageId, room });
  } catch (err) {
    console.warn('moderation unavailable, letting message through', err.message);
    return broadcast(room, { messageId, from: player.name, text });
  }

  for (const old of verdict.deleteMessages) removeMessage(old.room ?? room, old.messageId);
  if (verdict.allow) return broadcast(room, { messageId, from: player.name, text });

  const { action } = verdict;
  if (action.type === 'mute') player.mutedUntil = Date.now() + action.durationMs;
  if (action.type === 'ban') banPlayer(player.accountId);
  player.tell(action.message ?? `Message removed: ${verdict.reason}`);
}

Show first, or wait for the verdict?

Most messages come back quickly, but a message that goes to the AI can take a few seconds: Jev bundles messages for up to about two seconds before checking them. Pick one of two flows:

Show immediately, remove if flagged

Broadcast the message right away and call /v1/moderate in the background. If the verdict says allow: false, remove the message from everyone's chat by its messageId and apply the action. Chat feels instant; a bad message may be visible for a moment.

Recommended for most games.

Wait for the verdict

Hold the message until the verdict arrives, then broadcast it only if allow is true. Nothing bad is ever shown, but every message waits. Show the sender their own message straight away so it doesn't feel laggy.

Good for games for younger players.

In both cases, decide what happens if Jef Bot can't be reached (a timeout, a 5xx, a 429). Usually that's "let it through".

Tips and gotchas

  • Send every message, including ones that look harmless. Spam (6 messages in 10 seconds, the same message 3 times in a minute) and griefing or bullying patterns are spotted across a player's messages, and each room's recent messages become context for the next.
  • Use stable IDs. userId should be your player account ID. Use the same room value for the same chat channel.
  • Rate limit: 5, 20 or 50 requests per second per app (Free, Starter, Pro), with short bursts up to twice that. Over it you get 429 rate_limited with Retry-After: 1.
  • 403 plan_limit from /v1/moderate means the app is past your plan's app count (for example after a downgrade) and isn't moderated. Delete an older app or upgrade.
  • AI allowance: each plan has a monthly number of AI checks, and at most a tenth of it can be used per UTC day. When either runs out, only the free checks run and responses include "aiSkipped": "quota".
  • action.type: "delete" happens when a player breaks the rules again within 10 seconds of being punished (a flood): the message goes, but they aren't punished twice.
  • Add your own rules in the dashboard or with POST /v1/apps/{appId}/rules, e.g. "No sharing real-world addresses or phone numbers". See custom rules.
  • Staff tools: look up a player with GET /v1/apps/{appId}/users/{userId}, punish by hand with …/warn, undo with …/pardon. App keys can call these too. See the API reference.
  • Several game servers? Create more app keys for the same app (up to 10) so you can revoke one without touching the others.
